# Games catalogue and moderated game submissions

Website priority 3 · Asset and game sharing

Players can discover preserved and new games and try a creator’s work in progress. Creators can submit a game for catalogue review through a guided path, with GitHub PRs controlling publication.

## Done when

1. A player can distinguish preserved, released and in-progress games. A featured WIP has credited screenshots, a browser-playable build, a specific feedback request and a direct link to its Community topic. The topic links back to the same stable game URL.
2. A creator submits a playable WIP without editing repository files. A moderator can request changes, verify browser play and listing rights, and preview the static entry. A reviewed merge publishes the metadata and its links. Recovery leads stay in review until rights and availability are verified.
3. Walk one game from submission to publication to update. Preserve its public URL and topic on promotion, then exercise removal and rollback with the fixture so visitors see a valid catalogue in each state.

## Dependencies

- [Epic 29](../epic-community/epic-community.md) supplies the community topic links and first feedback round (29.2, 29.3).

## Scope

Use link-based intake and a human-reviewed GitHub PR. Website-hosted uploads, automatic PR creation and creator accounts can be reconsidered after the workflow is in use. The product repository owns the browser runner and supported package format.
